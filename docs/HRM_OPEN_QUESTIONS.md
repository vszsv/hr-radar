## Архитектурные вопросы

1. **UI-first или Agent-first?**
   Василий склоняется к UI-first: сначала рабочий интерфейс, потом AI-агент сверху. Аргумент — если AI отрубится (модели, API, бюджет), система должна работать руками. Это меняет приоритеты фазы 1.

2. **PostgreSQL или остаёмся на SQLite?**
   Спека предлагает PostgreSQL. Но для 3K кандидатов SQLite может быть достаточно и проще в деплое. Минус SQLite — нет нормального concurrent access для нескольких пользователей.

3. **Авторизация — как именно?**
   Сейчас HR Radar работает по ключу в URL (?key=). Для HRM нужны роли (HR, руководитель, админ). Полноценный auth (логин/пароль) или продолжаем ключами + роли?

4. **Отдельный проект или эволюция HR Radar?**
   Строить HRM как новый проект с чистой архитектурой или наращивать поверх существующего HR Radar (web_panel/app.py)?

## Вопросы по данным

5. **Резюме кандидатов — откуда брать?**
   FW API не отдаёт опыт/образование/курсы. Варианты:
   - Дособрать из HH API по sourceLink (~2,000 резюме)
   - Playwright-скрейпинг FW веб-интерфейса (все данные, но сложнее)
   - Забить на старые, начать собирать с нуля
   
6. **Фото кандидатов** — FW отдаёт photoId, но нет эндпоинта скачивания. Важно или нет?

7. **Файлы (PDF резюме, видео интервью)** — из FW не достать. Начинаем с нуля или есть локальные копии?

## Вопросы по процессам

8. **Воронка фиксированная или настраиваемая?**
   Спека предлагает настраиваемую (как Lever). Но может проще — одна фиксированная из 19 этапов БП?

9. **Скоркарты — нужны в фазе 1?**
   Или хватит свободных комментариев + AI-оценки на первое время?

10. **SLA — жёсткие или мягкие?**
    Блокировать переход на следующий этап при просрочке или только уведомлять?

## Вопросы по интеграциям

11. **WhatsApp — через какой сервис?**
    WhatsApp Business API (дорого, официально) или wwebjs/Baileys (бесплатно, серая зона)?

12. **Telegram — один бот или два?**
    Сейчас есть hr-radar-control бот. Для HRM — расширять его или отдельный бот?

## Приоритет на понедельник

Главный вопрос: **какой минимальный UI даёт замену FriendWork?**
- Список кандидатов + поиск
- Карточка кандидата + лента событий  
- Список вакансий + kanban
- Смена статусов

Если это — всё, то фаза 1 реалистична за 2-3 недели.
