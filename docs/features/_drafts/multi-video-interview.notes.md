## Концепт фичи

- **Метафора:** несколько частей одной записи → одно интервью
- **Опыт пользователя:** загрузил 2-3 ссылки на части интервью, нажал «Анализировать» — получил один результат, как будто это было одно видео
- **Принцип:** N ссылок → N скачиваний → склейка аудио → один пайплайн
- **Чем НЕ является:** не несколько отдельных интервью; не сравнение кандидатов; не параллельный анализ

**Концепт подтверждён пользователем:** да

## Контекст и проблема

Интервью часто записывается в несколько частей (обрыв связи, пауза). Сейчас система принимает одну ссылку — пользователь вынужден вручную склеивать видео перед загрузкой. Нужно убрать этот шаг.

## Кто пользователь

HR-менеджер, проводит интервью через видеозвонок. Запись разбивается на 2-3 части, лежит на cloud.mail.ru или smail.ru.

## Скоуп

**Делаем:**
- В video-режиме: заменить одно поле URL на список полей с кнопкой «+»
- Бэкенд: скачать каждый URL, извлечь аудио, склеить через ffmpeg concat
- Поддержка cloud.mail.ru и прямых ссылок (уже есть `_download_from_cloud_mail` и `_download_direct`)

**НЕ делаем:**
- Не трогаем audio-режим и text-режим
- Не меняем Stage 2
- Не добавляем загрузку файлов (только URL)

## Технический контекст

- **Файлы:** `web_panel/app.py`, `web_panel/templates/interview.html`
- **Текущий эндпоинт:** `POST /api/interview/analyze` принимает `video_url: str = Form("")`
- **Скачка:** `_download_from_cloud_mail(url, dest)` и `_download_direct(url, dest)` уже есть
- **Аудио-извлечение:** `_extract_audio(video_path, audio_path)` — ffmpeg уже установлен
- **Склейка:** `ffmpeg -i concat:"f1.mp3|f2.mp3" -acodec copy out.mp3` или через filter_complex
- **Пайплайн:** `_run_interview_pipeline` принимает `video_url: str` — нужно добавить `video_urls: list`
- **UI:** Alpine.js, поле `video_url` → массив `videoUrls: ['']` с кнопкой добавления/удаления

## Риски

- ffmpeg concat требует одинаковый кодек у всех частей; при разных — нужен re-encode (медленнее)
- Длинные интервью из 3+ частей = больше времени на скачку и склейку
