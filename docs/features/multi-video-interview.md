## 1. Обзор

Добавляем возможность загрузить несколько URL-ссылок на видео для одного интервью. Система скачивает все части, склеивает аудио в одну дорожку и запускает стандартный пайплайн транскрипции и анализа. Для HR-менеджера, интервью которого разбилось на 2-3 записи, результат будет как от одного цельного файла.

---

## 1.5 Концепт фичи

**Метафора / аналог:** несколько частей одной записи → одно интервью. Как склеить разорванную плёнку — зритель видит цельный фильм.

**Опыт пользователя:** HR-менеджер загрузил ссылки на 2-3 части интервью (обрыв связи, пауза), нажал «Анализировать» — получил один результат, как будто это было одно непрерывное видео. Ничего склеивать вручную не нужно.

**Главный принцип:** N ссылок → N скачиваний → склейка аудио → один пайплайн.

**Чем НЕ является (концептуально):**
- Не несколько отдельных интервью разных кандидатов
- Не сравнение кандидатов между собой
- Не параллельный анализ нескольких записей

---

## 2. Проблема и контекст

**Что сейчас происходит:**
- Система принимает ровно одну ссылку на видео
- Если интервью записалось частями, пользователь вынужден вручную склеивать видео перед загрузкой
- Это внешний ручной шаг, который тормозит процесс

**Почему важно решить сейчас:**
- Реальный кейс: интервью в двух частях на cloud.mail.ru / smail.ru
- Убирает ручной шаг и снижает барьер использования модуля

**Связанные материалы:**
- Модуль оценки интервью: `http://89.167.49.12:8093/interview?key=hrpanel2026`

## 3. Цели и не-цели

### В скоупе
- В video-режиме: заменить одно поле URL на динамический список (кнопка «+» добавляет поле, «×» удаляет)
- Минимум 1 URL обязателен, максимум не ограничен
- Бэкенд: скачать каждый URL последовательно, извлечь аудио из каждого, склеить через ffmpeg concat в один файл
- Поддержка cloud.mail.ru и прямых ссылок (логика уже есть)

### Не в скоупе (явно исключено)
- Не трогаем audio-режим и text-режим
- Не трогаем Stage 2
- Не добавляем загрузку файлов (только URL)
- Не добавляем прогресс-бар на скачку каждой части

## 5. Функциональные требования

- **FR-1:** В video-режиме поле ввода URL заменяется на список — минимум одно поле, кнопка «+ Добавить часть» добавляет новое, кнопка «×» удаляет (кроме последнего поля).
- **FR-2:** Кнопка «Анализировать» активна, если заполнен хотя бы один URL.
- **FR-3:** Бэкенд принимает список URL через повторяющееся поле формы `video_urls`.
- **FR-4:** Каждый URL скачивается последовательно в отдельный файл в рабочей директории задачи.
- **FR-5:** Из каждого скачанного файла извлекается аудио через `_extract_audio`.
- **FR-6:** Все аудио-файлы склеиваются через `ffmpeg concat` в один файл `merged_audio.mp3`.
- **FR-7:** Склеенный файл передаётся в `_transcribe_audio` — дальше пайплайн без изменений.
- **FR-8:** Если один из URL недоступен — задача завершается с ошибкой и сообщением какой URL не скачался.
- **FR-9:** Обратная совместимость: если передан один URL — поведение идентично текущему.

## 6. Технический дизайн

### 6.1 Архитектура / компоненты

```
[UI: список URL] → POST /api/interview/analyze (video_urls: List[str])
                           ↓
                  _download(url1) → audio1.mp3
                  _download(url2) → audio2.mp3
                           ↓
                  ffmpeg concat → merged_audio.mp3
                           ↓
                  _transcribe_audio(merged_audio.mp3)
                           ↓
                  [стандартный пайплайн без изменений]
```

### 6.2 API

#### `POST /api/interview/analyze`

Текущий параметр `video_url: str` заменяется на повторяющееся поле `video_urls`.

**Запрос (multipart/form-data):**
```
video_urls=https://cloud.mail.ru/part1
video_urls=https://cloud.mail.ru/part2
vacancy=new_business
model=claude-opus-4-8
input_mode=video
```

**Ответ `200 OK`:**
```json
{ "task_id": "uuid" }
```

**Ошибки:**
| Код | Причина |
|-----|---------|
| 400 | Нет ни одного URL в video-режиме |
| 400 | URL №N недоступен (сообщение с указанием URL) |

### 6.4 Прочее

Склейка аудио через ffmpeg:
```bash
# Создаём файл списка для ffmpeg concat demuxer
file 'audio_part_0.mp3'
file 'audio_part_1.mp3'

ffmpeg -f concat -safe 0 -i filelist.txt -c copy merged_audio.mp3
```

При разных кодеках частей — добавить `-c:a libmp3lame` вместо `-c copy` (ре-энкодинг).

## 9. Риски и ограничения

| # | Риск | Вероятность | Влияние | Митигация |
|---|------|-------------|---------|-----------|
| R-1 | Части записаны в разных кодеках — `-c copy` не сработает | Средняя | Среднее | Fallback на ре-энкодинг `-c:a libmp3lame` |
| R-2 | Один из URL недоступен (истёк срок ссылки) | Средняя | Высокое | Явная ошибка с указанием проблемного URL |
| R-3 | Большой суммарный объём (3 части × 1 GB) = долгое скачивание | Низкая | Среднее | Прогресс-стадия «скачивание» уже есть в UI |
