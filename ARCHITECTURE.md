# Архитектура HR Radar

## Поток данных
1. **IMAP Intake**
   - Чтение писем HH из профиля (`profiles.yaml`)
2. **HTML Parsing**
   - Извлечение кандидатов и ссылок на резюме
3. **Dedup**
   - Фильтрация по `seen_links` в SQLite
4. **LLM Scoring**
   - Батч-оценка по каждой активной роли
5. **Reporting**
   - Сводка + карточки релевантных кандидатов в Telegram

## Модель конфигурации
- `config/profiles.yaml` — «что может система» (профили/роли)
- `data/radar_controls.json` — «что сейчас включено» (runtime-тумблеры)

Итог: роли можно держать в конфиге, а включать/выключать кнопками без правок кода.

## Базы
На профиль создаётся отдельная БД (`data/<profile>.db`):
- `seen_links` — чтобы не слать дубль кандидатов
- `runs` — статистика запусков по роли

## Масштабирование
Добавление новой роли:
1) Добавить роль в `profiles.yaml`
2) Создать `config/prompts/<role>.txt`
3) Роль автоматически появится в `/radar` меню

Добавление нового профиля:
1) Секция профиля в `profiles.yaml`
2) IMAP креды в `.env`
3) Опционально отдельный timer/service
